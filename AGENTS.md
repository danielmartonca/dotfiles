# AGENTS.md

Personal dotfiles: shell config, small helpers, and Claude Code mods. **This repository is public.**

## Rule one: nothing employer- or machine-specific

Before every commit, check the diff for:

- company names, internal hostnames and URLs, Jira project keys, internal repo names, colleagues' names;
- secrets of any kind (tokens, keys, passwords), even in tests or comments;
- personal email addresses (commits use the GitHub no-reply address).

Anything like that belongs in one of the local files below, which the repo only references and never contains.
Tests use made-up names (`acme.*`, `example.com`, `ABC-123`).

| Local file (not in the repo) | Used by |
| --- | --- |
| `~/.zshrc.local` | sourced at the end of `.zshrc` |
| `~/.claude/CLAUDE.work.md` | imported at the end of `~/.claude/CLAUDE.md` |
| `~/.config/dotfiles/local.sh` | run at the end of `install.sh` (gets `DRY=1` on a dry run) |

If a change only makes sense with those local values, put the value in the local file and make the repo code
read it, or keep the change local altogether. Ask the owner when unsure.

## Layout

| Path | Installed to |
| --- | --- |
| `shell/zshrc`, `bashrc`, `profile`, `terraformrc` | `~/.zshrc`, `~/.bashrc`, `~/.profile`, `~/.terraformrc` |
| `bin/*` | `~/.local/bin/` |
| `claude/mods/<name>/` | `~/.claude/mods/<name>/`, listed in `CLAUDE_CODE_PLUGIN_DIRS` in `~/.claude/settings.json` |
| `claude/CLAUDE.md` | `~/.claude/CLAUDE.md` (the owner's global Claude Code instructions) |
| `claude/settings.json` | `~/.claude/settings.json`, only when none exists; otherwise only the mod list is merged |
| `install.sh` | the installer |

## How changes flow

`install.sh` **copies**, it does not symlink. The live files are what actually runs, so:

1. Edit the live file (e.g. `~/.claude/mods/git-mods/hooks/register.tsx`, `~/.zshrc`), or edit the repo and run
   `./install.sh` to copy it out.
2. `./install.sh collect` copies the live files back into the repo.
3. Review `git diff` against rule one, then commit.

`./install.sh --dry-run` shows what an install would change. A clean machine should show nothing.
Anything an install replaces is backed up under `~/.dotfiles-backup/<timestamp>/`.

A new top-level file or mod needs an entry in `FILES` or `DIRS` in `install.sh`, and a row in the README.

## Claude Code mods

Each mod is a folder with `.claude-plugin/plugin.json`, `hooks/hooks.json`, `hooks/register.tsx`, `types/index.d.ts`
and `tests/`.

- `claude plugin validate <mod folder>` and `claude plugin test <mod folder>` must pass before committing.
  Some tests already have type warnings; don't add new ones.
- `.claude-plugin/types/` is generated by Claude Code when the mod loads. It is gitignored and excluded from install.
- A mod change takes effect after Claude Code restarts.
- `git-mods` is the git button bar (Commit, Open PR, Clean, Archive). Clean deletes merged local branches, and
  their remote copy only when every commit on it is the owner's; keep that safety check intact.

## Conventions

- Commits: one imperative subject line under 72 characters, no body, never a `Co-Authored-By` trailer or a mention of AI.
- Line endings are LF (`.gitattributes`); scripts break with CRLF.
- Comments: one line, explaining why, not what.
- Don't force-push or rewrite history without asking the owner.
